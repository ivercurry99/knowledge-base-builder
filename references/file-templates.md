# 目录结构与文件模板

> 本文件是骨架的权威说明。能运行脚本时优先用 `scripts/scaffold_kb.py` 生成（结果与本文件一致）；宿主无法运行 Python 时，按本文件手工创建同样结构。

## 目录结构

```text
<根目录>/
├── README.md
├── 00-Inbox/
│   ├── 资源/                # 临时收藏的文章、链接
│   ├── 灵感/                # 不限领域的想法碎片
│   └── 待沉淀/              # 学过但没吃透的内容，按领域镜像 Areas
│       ├── {领域A}/
│       ├── {领域B}/
│       └── {领域C}/
├── 10-Areas/
│   ├── {领域A}/             # 领域用纯名称，不带数字前缀
│   │   ├── 1-{子领域}/
│   │   └── 2-{子领域}/
│   ├── {领域B}/
│   └── {领域C}/
├── 20-Projects/
│   ├── ing/                 # 进行中
│   ├── done/                # 已完成
│   └── wait/                # 暂停等待
├── 30-Output/
│   ├── ing/
│   ├── done/
│   └── wait/
├── 40-Skills/
│   └── README.md            # 执行工具箱 hub
└── 90-{昵称}的大脑说明/
    ├── README.md            # 大脑说明书（最高优先级入口）
    ├── 个人档案.md           # 用户档案
    ├── agents.md            # AI 操作约束（Harness）
    ├── 初始化提示词.md        # 换新会话时发送的完整恢复提示词
    ├── 文件追踪.md           # 文件移动/重命名时的链接更新机制
    └── 备份方案.md           # 定期备份方案
```

关键规则：

- 领域文件夹用**纯名称**（如 `数据分析`），子领域才用数字前缀（如 `1-业务理解`）。
- `00-Inbox/待沉淀/` 镜像 `10-Areas/` 的领域（不含子领域），升格时一一对应。
- 子领域可选，用户不给就留空，用的时候再建。

## frontmatter 约定

每个生成的文件都带 YAML frontmatter：

```yaml
---
tags:
  - <标签>
created: <YYYY-MM-DD>
type: <类型>
---
```

`type` 取值：

| type | 用于 |
|------|------|
| `root` | 根 README |
| `index` | 大脑说明书 README |
| `profile` | 个人档案（另加 `priority: P0`） |
| `constraint` | AI 操作约束 |
| `skill` | 初始化提示词、文件追踪、备份方案等工具笔记 |
| `skill-hub` | 40-Skills 的 hub README |

## 8 个生成文件

脚本生成 8 个文件：根 `README.md` + `40-Skills/README.md` + 大脑说明 6 个。各文件的完整模板以 `scripts/scaffold_kb.py` 为准，此处说明每个文件的作用：

| 文件 | 作用 |
|------|------|
| `README.md` | 知识库总览：结构 + 流转 + AI 角色 |
| `40-Skills/README.md` | 执行工具箱 hub：记录已装/待装的技能 |
| `90-…/README.md` | 大脑说明书：回答「你是谁 / 想要什么 / AI 怎么帮」+ 知识库地图 |
| `90-…/个人档案.md` | 用户档案：基本盘 / 性格 / 待进步点 / 职业框架 / 人生理想 / 痛点 / 协作风格 / 决策原则 |
| `90-…/agents.md` | AI 操作护栏：完成标准、文件约束、建议 vs 执行、结构规则 |
| `90-…/初始化提示词.md` | 完整恢复提示词：含沉淀流程、升格三标准、文件命名规则、门禁、反焦虑铁律等 |
| `90-…/文件追踪.md` | 文件移动/重命名后的链接更新机制 |
| `90-…/备份方案.md` | GitHub 私有仓库 + 本地压缩两种备份方式 |
